## Scope and method

This is an automated simulated-use review, not a study with real people. Five isolated Playwright browser contexts were used to operate the visible editor and generated websites. The test driver used accessible names and ordinary browser actions, without reading application source, React state, browser storage, or private APIs during this baseline. It adapted a few selectors using the rendered accessibility tree; the initial selector misses below are test-driver mistakes and are not counted as product errors.

The local production preview was served at `http://127.0.0.1:4174/`. The exported ZIPs were downloaded through the editor, extracted, and served through ordinary Python HTTP servers at root and nested paths. The browser runs used Chromium 156.0.8078.4 and Firefox 157.0. Node was 22.22.1 and npm 12.0.2; npm warned that this Node patch version is below its declared supported range. No reference video or video file was present in the repository, so visual assessment uses the written requirements only.

Screenshots and traces from the pre-remediation run are in [`artifacts/baseline/`](artifacts/baseline/). Each `persona-*.trace.zip` preserves browser screenshots and DOM snapshots without source files. Persona screenshots are automated evidence of rendered states, not evidence of human preference or task time.

## Initial assessment

The editor supports the essential creation path: choose a starter and theme, replace headings and rich text, upload and describe an image, add and edit sections and repeated entries, adjust layout and motion, preview phone/tablet/desktop widths, save locally, create an editable backup, and download a separate website ZIP. In the observed sessions, save status became “Saved on this browser,” reload restored edits, malformed backup import preserved the current site, and unsupported image upload produced a clear format error.

The main verified friction is publishing guidance. The onboarding's final step tells users to “follow the publishing guide” but exposes no publishing link. The exported `PUBLISH.txt` only says to upload files to a static host and gives no provider-specific path. A separate publishing guide exists in the repository, but the editor does not lead a first-time user to it. A second lower-severity issue is that a newly added rich-text field is visually blank without a visible label or placeholder, although it has the accessible name “Rich text introduction.”

No P0 or P1 usability defect was confirmed in the baseline journeys. Two P2 findings were corrected and verified below. This assessment does not establish WCAG conformance or production readiness.

## Baseline environment and quality gates

`npm ci` installed 244 packages from the lockfile and reported zero vulnerabilities. Formatting, lint, production build and prerender passed. Unit tests passed 156/156, with 94.50% statement, 89.84% branch, 95.48% function, and 96.29% line coverage. Browser tests passed 53/54. Chromium and Firefox project tests passed; the sole local failure was WebKit launch because host libraries (`libgtk-4`, `libgraphene`, GStreamer, and related libraries) are absent. This is an environment blocker, not an application assertion failure.

The independent SDK consumer check passed SDK-001 through SDK-006, including a clean consumer build and ZIP browser checks. The dependency license/provenance audit inspected 267 locked packages and passed. `npm audit --audit-level=moderate` reported zero vulnerabilities. The aggregate `npm run check` therefore exits nonzero on this host because its WebKit project cannot start.

The browser-suite performance-lab scenarios passed in the baseline run. A measured build/export/load timing baseline will be added with reproducible environment details after diagnosis; automated timings are not represented as human task-completion time.

## Extended baseline reliability observations

- A 110-character heading wrapped naturally on a 390px viewport without clipping the exported content.
- Deleting a section opened a confirmation dialog: “Delete this section? You can restore it with Undo.” Dismissing it preserved the section.
- A `.txt` file selected as an image was rejected with a clear PNG/JPEG/WebP format message.
- A damaged JSON backup was rejected with “This backup could not be opened. Your current project is unchanged.” The existing title remained unchanged.
- Local draft save status reached “Saved on this browser”; reloading restored the title.
- Uploaded artwork and alt text appeared in the generated site.

Browser storage exhaustion, interrupted network upload, and real assistive-technology use were not simulated. This editor has no network upload path; a screen reader was not installed. Actual screen-reader and physical mobile-keyboard checks remain human verification items.

## Export and visual baseline

The personal and Cyberpunk websites were generated by the editor, extracted, and served with Python's static HTTP server at `/` and `/howlscene/`. Both loaded with JavaScript enabled; essential headings, content, images, and alt text also existed and loaded with JavaScript disabled. There were no browser console errors or failed network responses. The Cyberpunk ZIP contained `index.html`, `site.css`, `site.js`, `favicon.svg`, `LICENSES.txt`, `PUBLISH.txt`, and only referenced image assets; it did not include editor assets. The animation-disable control appeared with JavaScript enabled and disappeared without JavaScript while semantic content remained.

Screenshots show visibly distinct themes: Ink Wash uses warm paper-like colors and layered painted scenery, Cyberpunk uses dark neon city styling, and Modern Professional uses a clean light layout. The Cyberpunk long-heading and phone layout remained readable in the captured state. These are simulated visual observations; no real user preference or equivalence to a missing reference video is claimed.
